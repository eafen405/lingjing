# ADR: 保持教程的技术原貌，不做现代化改造

课程的起始文件与配套素材是针对 legacy Input Manager、UGUI 与内置渲染管线编写的，而 Unity 2022.3 的默认配置恰好就是这一套。因此刻意**不**改用新 Input System、不换 UI Toolkit、不迁 URP —— 一旦改造，教程代码就对不上素材，复刻也变成了重写。Windows 玩家构建同样沿用编辑器内置的 Mono 后端，不额外安装 IL2CPP 模块，从而不依赖 Visual Studio 的 C++ 桌面开发工作负载。

这条决定对后续阶段成立的前提是：这一阶段的考核目标是复刻，不是工程现代化。

## 补充：统一采用课程的 2021.3 版起始文件

Unity Learn "Create with Code" 课程同时提供 6.0 与 2021.3 两个版本的起始文件，二者的输入实现不同：6.0 版用新 Input System（引用自动生成的 InputSystem_Actions 类与 InputAction 字段），2021.3 版用旧版 `Input.*`。

课程官方提供的 6.0 版开包里**不包含** `.inputactions` 资源与生成的输入类，单独导入会导致脚本无法编译；而 2021.3 版开包与课程另两个挑战（Challenge 3、Challenge 5）同代，本来就是旧版输入。

因此**四个挑战一律采用 2021.3 版起始文件**，使五个工程的输入方式、项目设置与素材完全同代，也与 Unity 2022.3 的默认输入设置一致。
